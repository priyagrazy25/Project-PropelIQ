# User Story - US_041

## Story ID
- ID: US_041

## Story Title
- No-Show Risk Model Training & Deployment

## Description
- As a system operator, I want an ML.NET classification model trained on appointment history data that calculates no-show risk scores (0-100) for each booking, so that the platform can proactively identify high-risk appointments and escalate reminders.

## Acceptance Criteria
1. **Given** appointment history data is available, **When** model training runs, **Then** the ML.NET classification model trains on patient history, appointment type, time slot, and historical no-show patterns per AIR-007.
2. **Given** a trained model, **When** deployed, **Then** the model is registered via the ML.NET pipeline and serves risk score predictions per TR-009.
3. **Given** the active model version, **When** a new model is deployed, **Then** the previous model version is maintained alongside the active version enabling rollback within 15 minutes per AIR-O03.
4. **Given** insufficient real patient history (initial launch), **When** model training runs, **Then** the model trains on synthetic appointment data until sufficient real history is accumulated.
5. **Given** a model rollback is triggered, **When** the operator switches versions, **Then** the system reverts to the previous model within 15 minutes with no service interruption.

## Edge Cases
- What happens when there is zero historical data at launch? (Synthetic data is seeded; model provides baseline predictions with lower confidence)
- What if the model's prediction accuracy degrades over time? (Periodic retraining on accumulated real data; agreement rate monitored; alerts triggered if accuracy drops)

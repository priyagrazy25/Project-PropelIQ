# User Story - US_034

## Story ID
- ID: US_034

## Story Title
- Document Embedding & Job Queue

## Description
- As a system operator, I want document chunk embeddings stored in SQL Server vector tables and extraction jobs managed through a sequential queue with circuit breaker protection, so that the platform supports RAG retrieval while preventing resource exhaustion on free-tier infrastructure.

## Acceptance Criteria
1. **Given** document chunks are extracted, **When** the embedding step runs, **Then** embeddings are stored in SQL Server custom vector table with indexed float arrays supporting cosine similarity search per AIR-R04.
2. **Given** multiple documents are uploaded concurrently, **When** extraction jobs are queued, **Then** a maximum of 2 concurrent extraction pipelines run at any time to prevent resource exhaustion per AIR-O04.
3. **Given** the Ollama inference service encounters 3 consecutive failures within 60 seconds, **When** the circuit breaker triggers, **Then** it opens and blocks requests for 120 seconds before attempting recovery per AIR-O02.
4. **Given** a document extraction request, **When** the token budget is enforced, **Then** 8,192 tokens per document extraction request is the maximum per AIR-O01.
5. **Given** the platform processes documents over time, **When** volume scales, **Then** the system supports 10,000 documents per month with linear scaling per NFR-016.

## Edge Cases
- What happens when the job queue is full and a new document is uploaded? (Document enters the queue in "Queued" status; patient sees their position in the processing queue)
- What if the circuit breaker is open when a new job is dequeued? (Job stays in "Queued" status and waits for circuit breaker recovery; no retries during open state)

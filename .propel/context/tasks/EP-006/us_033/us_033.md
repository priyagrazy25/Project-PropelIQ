# User Story - US_033

## Story ID
- ID: US_033

## Story Title
- NER Clinical Data Extraction

## Description
- As a clinical staff member, I want the system to extract structured clinical data (vitals, medical history, medications, allergies, lab results, diagnoses) from OCR-processed document text using biomedical NER, so that patient information is automatically categorized with confidence scores for verification.

## Acceptance Criteria
1. **Given** OCR-extracted and PII-redacted text chunks are available, **When** the NER pipeline runs, **Then** scispaCy (en_ner_bc5cdr_md) identifies biomedical entities including medications, diseases, chemicals, vitals, and lab results per AIR-001.
2. **Given** entities are extracted, **When** the system stores them, **Then** each ExtractedData record includes DataCategory, DataKey, DataValue, Unit, ConfidenceScore (0.0-1.0), and SourcePageReference per DR-005.
3. **Given** the extraction pipeline outputs data, **When** validation runs, **Then** structured output schema validity is maintained at 99% or higher against predefined JSON schemas per AIR-Q03.
4. **Given** the extraction evaluation is performed, **When** compared against annotated test sets, **Then** clinical data extraction recall rate meets or exceeds 90% per AIR-Q04.
5. **Given** extraction produces data points below 0.7 confidence, **When** stored, **Then** they are flagged as "Low Confidence" per DR-010.

## Edge Cases
- What happens when the document contains no recognizable clinical entities? (Extraction completes with zero results; document status updated with a note for staff review)
- What if the same entity appears multiple times with different confidence? (Highest confidence extraction is stored as primary; duplicates logged for conflict detection)

# User Story - US_032

## Story ID
- ID: US_032

## Story Title
- OCR & Text Extraction Pipeline

## Description
- As a clinical staff member, I want uploaded scanned and image-based PDFs to be automatically processed through an OCR pipeline, so that text content is extracted and made available for downstream NER extraction.

## Acceptance Criteria
1. **Given** a PDF document is queued for processing, **When** the extraction pipeline picks it up, **Then** Tesseract OCR 5.x extracts text from all pages including scanned/image-based content per TR-008.
2. **Given** a document up to 20 pages, **When** OCR completes, **Then** the total extraction finishes within 5 minutes per NFR-003.
3. **Given** extracted text contains patient-identifying information, **When** pre-processing runs, **Then** PII (name, SSN, DOB, contact) is redacted before passing content to NLP models per AIR-S02.
4. **Given** OCR extraction fails, **When** the error is caught, **Then** the document status is set to "Failed" with a ProcessingError message stored per DR-004.
5. **Given** the extracted text is ready, **When** chunking runs, **Then** the text is segmented into 512-token chunks with 10% overlap (51 tokens) per AIR-R01.

## Edge Cases
- What happens when a PDF contains zero extractable text (blank pages)? (Document marked as "Failed" with descriptive error; patient notified to re-upload)
- What if the OCR engine produces garbled output from poor-quality scans? (Low confidence triggers a quality flag; staff is alerted to review the source document)

# User Story - US_031

## Story ID
- ID: US_031

## Story Title
- Clinical Document Upload

## Description
- As a patient, I want to upload my clinical documents in PDF format through a drag-and-drop interface, so that the platform can process and extract my medical data without manual data entry.

## Acceptance Criteria
1. **Given** I am on the clinical documents page, **When** I drag one or more PDF files onto the upload zone, **Then** the system accepts the files and displays per-file upload progress indicators per UXR-106.
2. **Given** I upload a scanned or image-based PDF, **When** the upload completes, **Then** the system queues the document for OCR + NLP extraction and sets its status to "Queued".
3. **Given** an upload fails mid-transfer for one file in a batch, **When** the error occurs, **Then** the system retains successfully uploaded files and offers per-file retry without re-uploading the completed files per UXR-604.
4. **Given** I upload a file that is not a PDF, **When** the system validates the file type, **Then** it rejects the file with a descriptive error message and does not queue it for processing.
5. **Given** I upload a document, **When** it is stored, **Then** the file is saved to an encrypted storage path per DR-004 with a unique DocumentID, PatientID link, and processing status.

## Edge Cases
- What happens when the file exceeds the maximum allowed size? (System rejects with a clear message indicating the size limit)
- What if the user loses network connectivity during upload? (Partial uploads are discarded; user can retry when connectivity is restored)

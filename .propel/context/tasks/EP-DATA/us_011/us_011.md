# User Story - US_011

## Story ID
- ID: US_011

## Story Title
- Backup Infrastructure & Seed Data

## Description
- As a developer, I want automated database backups with 24-hour RPO and 4-hour RTO configured, and predefined dummy insurance records seeded through EF Core migrations, so that the platform has disaster recovery capability and the insurance pre-check feature has reference data from day one.

## Acceptance Criteria
1. **Given** backup automation is configured, **When** the scheduled backup runs, **Then** a full database backup is created in AES-256 encrypted format at a separate storage location per DR-014.

2. **Given** RPO is 24 hours, **When** I verify the backup schedule, **Then** backups execute at least once every 24 hours with retention of the last 7 backups.

3. **Given** RTO is 4 hours, **When** I perform a disaster recovery drill, **Then** the database is fully restored from the latest backup within 4 hours.

4. **Given** the seed migration exists, **When** I run EF Core migrations, **Then** the InsuranceRecords table is populated with predefined dummy insurance entries (InsuranceName, ValidMemberIDPattern) covering at least 10 insurance providers per DR-017.

5. **Given** seed data is idempotent, **When** the migration runs on an existing database with seed data, **Then** no duplicate records are created and existing records are not modified.

## Edge Cases
- What happens when the backup storage location is full? (Backup job alerts admin and retains the most recent backup; oldest backups are rotated)
- How does the system handle insurance seed data updates? (New migration adds/updates records without modifying existing entries; version-tracked)

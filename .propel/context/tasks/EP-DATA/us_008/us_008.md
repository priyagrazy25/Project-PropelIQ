# User Story - US_008

## Story ID
- ID: US_008

## Story Title
- Core Identity & Scheduling Entities

## Description
- As a developer, I want EF Core entity models for User, Patient, Provider, AppointmentSlot, Appointment, PreferredSlotSwap, Waitlist, and IntakeRecord created with code-first migrations, so that the identity and scheduling domain has a fully operational data layer.

## Acceptance Criteria
1. **Given** the data layer project exists, **When** I create entity models, **Then** User entity includes UserID (GUID PK), Email (unique), PasswordHash, FullName, DateOfBirth, ContactNumber, Address, Role (enum), Status (enum), CreatedAt, UpdatedAt per DR-001.

2. **Given** entity models are defined, **When** I create Appointment entity, **Then** it includes AppointmentID (GUID PK), PatientID (FK), ProviderID (FK), DateTime, Duration, Status (8-value enum), AppointmentType, CreatedAt, UpdatedAt per DR-002.

3. **Given** Provider and AppointmentSlot entities exist, **When** I inspect the model, **Then** Provider has ProviderID, Name, Specialty, Location, IsActive; and AppointmentSlot has SlotID, ProviderID (FK), DateTime, Duration, Status (Available/Booked/Released) per DR-003.

4. **Given** all entities are configured, **When** I run `dotnet ef migrations add InitialScheduling`, **Then** a sequential migration is generated creating all identity and scheduling tables with proper foreign key relationships.

5. **Given** the migration is applied, **When** I inspect the database, **Then** all tables, indexes, and foreign key constraints are created matching the ERD specification from models.md.

## Edge Cases
- What happens when a migration conflicts with an existing schema? (Migration fails with descriptive error; developer resolves conflicts before retrying)
- How does the system handle concurrent migration execution in team environment? (EF Core __EFMigrationsHistory table prevents duplicate migration application)

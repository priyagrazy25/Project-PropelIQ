# User Story - US_044

## Story ID
- ID: US_044

## Story Title
- Immutable Audit Logging

## Description
- As a compliance officer, I want all user actions involving patient data captured in immutable, append-only audit logs with before/after state snapshots, so that the platform maintains a complete HIPAA-compliant audit trail retained for 7 years.

## Acceptance Criteria
1. **Given** a user performs any PHI-touching action, **When** the action completes, **Then** an immutable audit log record is created capturing actor identity, action type, timestamp, affected resource, and before/after state snapshots per FR-031.
2. **Given** audit log tables, **When** database permissions are configured, **Then** no application role has UPDATE or DELETE permissions on audit log tables per DR-011.
3. **Given** AI model invocations occur, **When** the invocation completes, **Then** audit records include input/output token counts, model version, confidence scores, and processing duration per AIR-S03.
4. **Given** PHI appears in application code, **When** errors or log events occur, **Then** PHI is redacted from application logs, error messages, and stack traces — only the encrypted audit store contains PHI per NFR-011.
5. **Given** audit records accumulate, **When** retention policy is applied, **Then** all records are retained for a minimum of 7 years per DR-011.

## Edge Cases
- What happens if the audit logging service itself fails? (The primary operation continues but is flagged for audit gap; a background process retries logging from a transient queue)
- What if the audit store exceeds storage limits? (Archival process compresses and moves older records to cold storage while maintaining 7-year accessibility)

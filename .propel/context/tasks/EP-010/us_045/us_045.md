# User Story - US_045

## Story ID
- ID: US_045

## Story Title
- RBAC & Access Control Enforcement

## Description
- As a system administrator, I want role-based access control enforced with a deny-by-default policy and OWASP Top 10 security controls, so that patients access only their own data, staff access scoped data, and the platform is protected against common web vulnerabilities.

## Acceptance Criteria
1. **Given** the RBAC middleware is active, **When** any API request is made, **Then** deny-by-default is enforced ensuring patients access only their own data, staff access scoped patient data, and admins follow minimum necessary standard per FR-032 and NFR-009.
2. **Given** OWASP Top 10 controls, **When** the API processes requests, **Then** parameterized queries (via EF Core LINQ), Content Security Policy headers, HTTP Strict Transport Security, and input validation at all API boundaries are enforced per NFR-010.
3. **Given** authentication endpoints, **When** login attempts occur, **Then** rate limiting is applied to prevent brute-force attacks per NFR-010.
4. **Given** a patient attempts to access another patient's data, **When** the RBAC policy evaluates, **Then** the request is denied with a 403 Forbidden response.
5. **Given** AI model processing, **When** PHI is involved, **Then** zero PHI is transmitted to external AI providers — all inference runs locally per AIR-S01.

## Edge Cases
- What happens when a staff member's role is changed while they have an active session? (Role change takes effect on next token refresh; active session retains previous permissions until JWT expires in 15 minutes)
- What if an admin tries to access raw PHI beyond the minimum necessary standard? (Access is denied; the attempt is logged to the immutable audit trail)

# User Story - US_027

## Story ID
- ID: US_027

## Story Title
- Insurance Pre-Check Validation

## Description
- As a patient, I want to validate my insurance name and member ID against the system's records with immediate inline feedback, so that I know my insurance status before completing my appointment booking.

## Acceptance Criteria
1. **Given** I enter my insurance name and member ID, **When** I submit the validation form, **Then** the system checks against the predefined dummy insurance records and displays the result inline without page reload per UXR-105.
2. **Given** a full match is found, **When** both insurance name and member ID match, **Then** the system displays a green "Verified" status indicator.
3. **Given** a partial match occurs, **When** the name matches but member ID does not, **Then** the system displays an amber "Unverified - Member ID mismatch" warning and allows me to proceed with a flagged status.
4. **Given** no match is found, **When** neither name nor ID match any record, **Then** the system displays a red "Unverified - Insurance not recognized" warning with a note that it will be flagged for staff follow-up.
5. **Given** pre-check completes, **When** the validation status is recorded, **Then** staff can view the insurance verification status on their dashboard.

## Edge Cases
- What happens when the insurance records table is empty? (System returns "Verification unavailable" and allows patient to proceed without status)
- How does the system handle special characters in insurance names? (Input is sanitized; case-insensitive partial matching is applied)

# User Story - US_025

## Story ID
- ID: US_025

## Story Title
- Manual Form Intake

## Description
- As a patient, I want to complete my pre-visit intake using a traditional structured form with autosave, so that I can provide my medical history, symptoms, allergies, and medications with full control over field-level editing.

## Acceptance Criteria
1. **Given** I select manual form intake, **When** the form loads, **Then** structured fields for medical history, current symptoms, allergies, and medications are displayed with proper labels and placeholder text.
2. **Given** I am filling the form, **When** 30 seconds elapse, **Then** the system autosaves all entered data with a visible autosave indicator per UXR-505.
3. **Given** I submit the form, **When** validation fails, **Then** the system highlights invalid/missing fields with inline descriptive error messages per UXR-601.
4. **Given** I have submitted the intake, **When** I want to edit a field, **Then** I can directly edit any field without requiring staff assistance or restarting the intake per FR-017.
5. **Given** I switch to manual form from AI intake, **When** the form loads, **Then** all previously collected data from the AI session is pre-filled into the corresponding form fields.

## Edge Cases
- What happens when autosave fails due to network issues? (Local storage backup preserves data; retry on reconnection; user sees "Autosave failed - data preserved locally")
- How does the system handle browser back button during intake? (Navigation guard warns of unsaved changes; autosaved data is recoverable)

# User Story - US_006

## Story ID
- ID: US_006

## Story Title
- API Documentation & Testing Framework

## Description
- As a developer, I want RESTful API documentation auto-generated via Swagger/OpenAPI 3.0 and a testing infrastructure with xUnit (unit), WebApplicationFactory (integration), and Playwright (E2E), so that the team can maintain 80% unit and 60% integration test coverage targets.

## Acceptance Criteria
1. **Given** Swashbuckle is configured, **When** I navigate to /swagger, **Then** a fully interactive API documentation page is displayed with all registered endpoints, schemas, and versioned routes (v1/).

2. **Given** xUnit is installed, **When** I run unit tests, **Then** tests execute against the business logic layer using Moq for dependency isolation with code coverage reporting.

3. **Given** WebApplicationFactory is configured, **When** I run integration tests, **Then** tests execute against in-memory test server with Testcontainers providing a real SQL Server instance.

4. **Given** Playwright is installed, **When** I run E2E tests, **Then** cross-browser tests execute against the React SPA validating critical user flows.

5. **Given** test coverage is tracked, **When** I generate coverage reports, **Then** the report shows unit test coverage >= 80% for business logic and integration coverage >= 60% for API endpoints.

## Edge Cases
- What happens when Testcontainers cannot start SQL Server? (Tests fall back to in-memory database provider with clear warning in test output)
- How does the system handle Playwright browser download failures in CI? (Pre-download browsers in CI setup step; cache between runs)

# User Story - US_007

## Story ID
- ID: US_007

## Story Title
- Logging & Health Monitoring

## Description
- As a developer, I want Serilog structured logging with PHI-scrubbing enrichers and ASP.NET Core health check endpoints (/health/live, /health/ready), so that the team can monitor application health and debug issues without exposing Protected Health Information.

## Acceptance Criteria
1. **Given** Serilog is configured, **When** the application logs events, **Then** structured JSON log entries are written to Console and Seq free tier sinks with configurable log levels.

2. **Given** PHI-scrubbing enrichers are active, **When** a log entry contains patient data (name, DOB, SSN, email), **Then** the PHI fields are automatically redacted before being written to any log sink.

3. **Given** health check endpoints are registered, **When** I send GET to /health/live, **Then** the API returns 200 OK if the application process is running.

4. **Given** dependency health checks are registered, **When** I send GET to /health/ready, **Then** the API returns 200 OK only if SQL Server, Redis, and Ollama are reachable; otherwise 503 Service Unavailable with failing dependency details.

5. **Given** logging is operational, **When** an unhandled exception occurs, **Then** the error is logged with correlation ID, request context, and sanitized stack trace (no PHI).

## Edge Cases
- What happens when the Seq endpoint is unreachable? (Serilog buffers logs locally and retries; Console sink continues uninterrupted)
- How does the system handle log volume spikes? (Rate-limiting enricher caps writes to 1000 entries/minute per category)

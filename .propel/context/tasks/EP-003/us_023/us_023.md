# User Story - US_023

## Story ID
- ID: US_023

## Story Title
- Patient Arrival Marking

## Description
- As a Staff member, I want to mark a patient as "Arrived" for their scheduled appointment, so that the clinical team knows the patient is ready and self-check-in is prevented per system requirements.

## Acceptance Criteria
1. **Given** I am authenticated as Staff, **When** I select a scheduled appointment and click "Mark Arrived", **Then** the appointment status is updated to "Arrived" with a timestamp.
2. **Given** arrival marking is staff-only, **When** a Patient user attempts to access the arrival endpoint, **Then** the system returns 403 Forbidden.
3. **Given** the system does not support self-check-in, **When** I inspect patient-facing screens, **Then** no check-in button, QR code, or self-arrival option is present anywhere in the patient portal.
4. **Given** a patient is marked as arrived, **When** the status is updated, **Then** the queue display and staff dashboard reflect the arrival in real-time via WebSocket.
5. **Given** an arrival is marked, **When** the action completes, **Then** an audit log entry records the staff actor, appointment ID, and arrival timestamp.

## Edge Cases
- What happens when staff tries to mark arrival for a cancelled appointment? (System rejects with "Cannot mark arrival for cancelled appointment" validation error)
- How does the system handle marking arrival for a future-date appointment? (System rejects with "Arrival can only be marked on appointment day" validation error)

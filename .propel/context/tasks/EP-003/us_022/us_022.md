# User Story - US_022

## Story ID
- ID: US_022

## Story Title
- Same-Day Queue Management

## Description
- As a Staff member, I want to view and manage the same-day walk-in queue with real-time status updates, so that I can track patient flow and update statuses as patients are seen.

## Acceptance Criteria
1. **Given** I open the queue management view, **When** the page loads, **Then** I see an ordered list of today's patients with status indicators (Waiting, In-Progress, Completed) and skeleton loading during data fetch per UXR-501.
2. **Given** the queue is displayed, **When** I change a patient's status (Waiting to In-Progress to Completed), **Then** the status update is persisted and broadcast to all connected staff clients via WebSocket within 500ms per UXR-503.
3. **Given** a new walk-in is registered by another staff member, **When** the patient is added to the queue, **Then** my queue view updates in real-time without manual refresh.
4. **Given** I view the queue, **When** I inspect a patient entry, **Then** I can see arrival time, appointment type, and current wait duration.
5. **Given** all status changes are tracked, **When** a status update occurs, **Then** an immutable audit log entry is created with the staff actor, action, and timestamp.

## Edge Cases
- What happens when two staff members update the same patient simultaneously? (WebSocket reconciliation resolves conflict; latest update wins with optimistic concurrency)
- How does the system handle a patient who leaves without being seen? (Staff marks patient as "Left" or "No-Show" with audit trail)

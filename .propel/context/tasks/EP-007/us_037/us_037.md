# User Story - US_037

## Story ID
- ID: US_037

## Story Title
- Staff Conflict Resolution Workflow

## Description
- As a clinical staff member, I want to resolve detected data conflicts through a side-by-side comparison interface showing source documents, so that I can make informed decisions and record my resolution with an audit trail.

## Acceptance Criteria
1. **Given** conflicts are flagged in the 360-view, **When** I click "Resolve" on a conflict, **Then** a side-by-side comparison interface displays the conflicting values with source document links per UXR-108.
2. **Given** the resolution interface, **When** I select a resolution (accept side A, accept side B, or enter a manual override), **Then** the chosen value is applied to the 360-view and the conflict status is updated to "Resolved".
3. **Given** I resolve a conflict, **When** the resolution is saved, **Then** an audit record captures my identity, the resolution action, the before/after state, and a timestamp.
4. **Given** resolved conflicts, **When** the data retention policy applies, **Then** clinical data and resolution history are retained for the patient account lifecycle plus 7 years per DR-012.
5. **Given** multiple conflicts exist, **When** I resolve them, **Then** each conflict can be resolved independently and the 360-view updates incrementally.

## Edge Cases
- What happens if two staff members try to resolve the same conflict simultaneously? (Optimistic concurrency prevents overwrite; the second user sees a notification that the conflict was already resolved and must refresh)
- What if a new document upload introduces a new conflict on an already-resolved data point? (A new conflict is created referencing the new source; previous resolution remains in history)

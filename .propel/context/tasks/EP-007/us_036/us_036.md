# User Story - US_036

## Story ID
- ID: US_036

## Story Title
- Data Conflict Detection & Highlighting

## Description
- As a clinical staff member, I want the system to detect and explicitly highlight critical data conflicts across multiple uploaded documents (e.g., conflicting medications, inconsistent allergies) with source document references, so that I can identify and prioritize safety-critical discrepancies.

## Acceptance Criteria
1. **Given** a patient has data extracted from multiple documents, **When** the aggregation engine compares entries of the same category, **Then** contradictions (conflicting medication dosages, inconsistent allergy records, contradictory diagnoses) are flagged per FR-026 and AIR-006.
2. **Given** a conflict is detected, **When** stored, **Then** the DataConflict record includes severity classification (Critical or Warning), source document references for both sides, and the conflicting data values.
3. **Given** the 360-view displays data points, **When** confidence scores are shown, **Then** color-coded indicators render: green >= 0.7, amber 0.5-0.7, red < 0.5 per UXR-107.
4. **Given** conflicts exist, **When** the 360-view is displayed, **Then** Critical conflicts are highlighted prominently with a banner alert and Warning conflicts are shown inline with the affected data section.
5. **Given** staff reviews a conflict, **When** they click on it, **Then** source document references are linked enabling navigation to the original document and page.

## Edge Cases
- What happens when conflicts are detected in the same document? (Intra-document conflicts are flagged with a "Same Source" indicator and lower severity by default)
- What if all data points agree across documents? (No conflicts are displayed; the 360-view shows a "Verified" status badge on each section)

# User Story - US_018

## Story ID
- ID: US_018

## Story Title
- Dynamic Preferred Slot Swap

## Description
- As a patient, I want to register a preferred unavailable slot alongside my confirmed booking so that the system automatically swaps my appointment if my preferred slot becomes available.

## Acceptance Criteria
1. **Given** I am booking an appointment, **When** I select a preferred unavailable slot alongside my confirmed slot, **Then** the system registers a PreferredSlotSwap record with FIFO priority.

2. **Given** my preferred slot becomes available (cancellation/reschedule), **When** the system evaluates swap eligibility, **Then** it processes the first-registered (FIFO) swap request and automatically moves my appointment to the preferred slot.

3. **Given** the swap executes successfully, **When** the original slot is released, **Then** it becomes available in the pool, waitlisted patients are notified, and I receive SMS and email confirmation of the swap.

4. **Given** I have a synced calendar event, **When** the swap executes, **Then** the calendar event is automatically updated with the new appointment time.

5. **Given** multiple patients prefer the same slot, **When** the slot becomes available, **Then** only the first-registered patient gets the swap; remaining patients retain their original appointments.

## Edge Cases
- What happens when the preferred slot's provider changes after registration? (System removes the swap request and notifies the patient that the preferred slot is no longer compatible)
- How does the system handle a swap when the patient cancels the original appointment? (Swap request is automatically expired when the base appointment is cancelled)

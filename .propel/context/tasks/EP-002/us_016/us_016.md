# User Story - US_016

## Story ID
- ID: US_016

## Story Title
- Provider Search & Slot Display

## Description
- As a patient, I want to search for available providers by specialty, provider name, and date range with real-time slot availability, so that I can find and select the most convenient appointment time.

## Acceptance Criteria
1. **Given** I am on the provider search page, **When** I enter a specialty, provider name, or date range, **Then** the system returns matching providers with available slots within 2 seconds at p95 per UXR-101.

2. **Given** search results are displayed, **When** another user books a displayed slot, **Then** the slot disappears from my view within 500 milliseconds via SignalR WebSocket without page reload per UXR-102.

3. **Given** results are loading, **When** the API request is in progress, **Then** skeleton loading screens are displayed preserving the expected layout structure.

4. **Given** I search with filters, **When** no providers match my criteria, **Then** the system displays an empty state with "No providers match your criteria" and a filter reset CTA.

5. **Given** the cache layer is active, **When** I execute a search, **Then** the system checks Upstash Redis L1 cache (30s TTL) before querying the database, reducing database load.

## Edge Cases
- What happens when SignalR connection drops during search? (Client auto-reconnects; missed slot updates are reconciled via REST API fallback call)
- How does the system handle very broad searches returning 100+ results? (Paginate results at 20 per page with virtual scrolling)

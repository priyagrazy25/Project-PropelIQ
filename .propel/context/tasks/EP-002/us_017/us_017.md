# User Story - US_017

## Story ID
- ID: US_017

## Story Title
- Appointment Booking & Confirmation

## Description
- As a patient, I want to select and confirm an available appointment slot with optimistic UI feedback, so that I receive immediate confirmation of my booking with a unique appointment ID.

## Acceptance Criteria
1. **Given** I have selected a provider and time slot, **When** I click "Confirm Booking", **Then** the system records the appointment with a unique appointment ID, patient ID, provider, date, time, and status "Confirmed".

2. **Given** the booking API is idempotent, **When** the same booking request is submitted twice (network retry), **Then** the system returns the existing appointment rather than creating a duplicate per NFR-019.

3. **Given** I click the confirm button, **When** the UI applies optimistic booking, **Then** the slot appears immediately as booked in my view, with automatic rollback if the API returns an error per UXR-502.

4. **Given** the booking succeeds, **When** I view the confirmation screen, **Then** the appointment details (provider, date, time, location) are displayed with the unique appointment ID.

5. **Given** a booking conflict occurs (slot taken between search and confirm), **When** the API returns 409 Conflict, **Then** the UI rolls back the optimistic update and displays "Slot no longer available" with a prompt to select another.

## Edge Cases
- What happens when the patient's session expires during booking? (Silent token refresh; if refresh fails, session timeout modal appears with context preservation)
- How does the system handle database transaction failure during slot reservation? (Transaction rollback releases the slot lock; 500 error returned; patient can retry)

# User Story - US_013

## Story ID
- ID: US_013

## Story Title
- User Login & JWT Authentication

## Description
- As a registered user, I want to log in with my email and password to receive a JWT token with role-based access, so that I can securely access platform features appropriate to my role (Patient, Staff, Admin).

## Acceptance Criteria
1. **Given** I am on the login page, **When** I enter valid credentials, **Then** the system authenticates me using Argon2id password verification (3 iterations, 64 MB memory, 1 parallelism) and returns a short-lived JWT access token with my role claim.

2. **Given** authentication succeeds, **When** the JWT is issued, **Then** a single-use refresh token is also issued for token rotation, preventing replay attacks per TR-006.

3. **Given** I submit invalid credentials, **When** the login request fails, **Then** the system returns a generic "Invalid email or password" message without revealing which field is incorrect.

4. **Given** I am authenticated, **When** my JWT access token expires (15 minutes), **Then** the frontend silently refreshes the token using the refresh token without interrupting my session.

5. **Given** rate limiting is active, **When** more than 5 failed login attempts occur from the same IP in 5 minutes, **Then** the system temporarily blocks further attempts and returns a 429 Too Many Requests response.

## Edge Cases
- What happens when a deactivated user attempts to log in? (System returns "Account deactivated. Contact administrator." without revealing account existence)
- How does the system handle concurrent login from multiple devices? (Each device gets its own refresh token; old refresh tokens are invalidated on rotation)

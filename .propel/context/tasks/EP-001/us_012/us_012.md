# User Story - US_012

## Story ID
- ID: US_012

## Story Title
- Patient Registration

## Description
- As a new patient, I want to register an account using my email with demographic information capture, so that I can access the platform's appointment booking and clinical features.

## Acceptance Criteria
1. **Given** I am on the registration page, **When** I enter valid email, password, name, date of birth, contact number, and address, **Then** the system creates my account and redirects me to the login page with a success message.

2. **Given** I am completing registration, **When** I submit a form with missing required fields, **Then** the system displays inline validation errors below each offending field with descriptive messages per UXR-601.

3. **Given** I enter an email address, **When** the email format is invalid or already registered, **Then** the system displays an immediate validation error without submitting the form.

4. **Given** I set a password, **When** the password does not meet complexity requirements (8+ characters, uppercase, number, special character), **Then** the system displays specific password requirements that are not met.

5. **Given** the registration API is called, **When** the request completes, **Then** the response is returned within 2 seconds at the 95th percentile per NFR-001.

## Edge Cases
- What happens when a user submits the form with JavaScript disabled? (Server-side validation catches all errors and returns appropriate error responses)
- How does the system handle concurrent registrations with the same email? (Database unique constraint on Email prevents duplicates; second request returns 409 Conflict)

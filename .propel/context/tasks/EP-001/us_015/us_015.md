# User Story - US_015

## Story ID
- ID: US_015

## Story Title
- Admin User Management

## Description
- As an Admin, I want to create, update, and deactivate user accounts and assign roles (Patient, Staff, Admin), so that I can manage platform access and maintain proper user lifecycle governance.

## Acceptance Criteria
1. **Given** I am authenticated as Admin, **When** I navigate to user management, **Then** I see a searchable, paginated list of all user accounts with name, email, role, and status.

2. **Given** I am creating a new user, **When** I submit the creation form with name, email, and role, **Then** the system creates the account with Argon2id-hashed password and sends an account creation notification email.

3. **Given** I enter a duplicate email during user creation, **When** I submit the form, **Then** the system rejects the creation with a 409 Conflict and displays "Email already registered."

4. **Given** I am deactivating a user account, **When** I confirm the deactivation, **Then** the system sets the user status to Deactivated (soft-delete), disables login, and preserves all data for audit purposes per DR-008.

5. **Given** any user management action completes, **When** the operation succeeds, **Then** an immutable audit log entry is created with actor ID, action, resource, timestamp, and before/after state.

## Edge Cases
- What happens when an Admin tries to deactivate their own account? (System prevents self-deactivation to avoid lockout; returns validation error)
- How does the system handle role change for a user with active sessions? (Existing JWT remains valid until expiry; new role enforced on next token refresh)

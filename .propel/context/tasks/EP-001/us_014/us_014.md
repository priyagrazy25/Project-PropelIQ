# User Story - US_014

## Story ID
- ID: US_014

## Story Title
- Session Timeout & Re-authentication

## Description
- As an authenticated user, I want the system to automatically time out my session after 15 minutes of inactivity with a warning modal before expiry, so that my Protected Health Information is secured from unauthorized access per HIPAA requirements.

## Acceptance Criteria
1. **Given** I am authenticated and inactive for 14 minutes, **When** the timeout warning triggers, **Then** a modal dialog appears with a 60-second countdown timer offering "Extend Session" and "Logout" options per UXR-603.

2. **Given** the timeout modal is displayed, **When** I click "Extend Session", **Then** the session timer resets to 15 minutes and I remain on the current page with all form data preserved.

3. **Given** 15 minutes of inactivity elapses without interaction, **When** the session expires, **Then** both the JWT access token and refresh token are invalidated and I am redirected to the login page.

4. **Given** my session has expired, **When** I re-authenticate, **Then** I am returned to the same page URL I was on before timeout (preserving context).

5. **Given** an API call fails with 401 Unauthorized, **When** the frontend detects the expired token, **Then** it displays a global error banner with a "Re-authenticate" action per UXR-602.

## Edge Cases
- What happens when the timeout modal appears during a form submission? (Form submission completes first; timeout resets on successful API response)
- How does the system handle timeout in multiple browser tabs? (All tabs detect token invalidation via shared storage event; all show re-auth prompt)

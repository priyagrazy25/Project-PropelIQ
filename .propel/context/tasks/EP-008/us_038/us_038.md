# User Story - US_038

## Story ID
- ID: US_038

## Story Title
- ICD-10 Code Mapping

## Description
- As a clinical staff member, I want the system to map ICD-10-CM codes from diagnoses identified in the 360-Degree Patient View, presenting top-3 candidate codes ranked by confidence, so that I can verify and approve accurate diagnostic codes efficiently.

## Acceptance Criteria
1. **Given** the 360-Degree Patient View contains diagnoses, **When** ICD-10 mapping runs, **Then** the system maps ICD-10-CM codes using NER-based classification and lookup table matching per AIR-004.
2. **Given** mapping produces results, **When** candidates are displayed, **Then** the top-3 codes are ranked by confidence score with color-coded indicators (green/amber/red).
3. **Given** a mapping request, **When** the AI processes it, **Then** the token budget of 4,096 tokens per request is enforced per AIR-O01.
4. **Given** mapped codes, **When** stored, **Then** each MedicalCode record includes CodeID, PatientID, CodeType (ICD10), Code, Description, ConfidenceScore, and Status ("Suggested") per DR-007.
5. **Given** all AI-generated codes, **When** created, **Then** they enter with "Suggested" status requiring explicit staff verification per AIR-S04.

## Edge Cases
- What happens when no diagnosis is identified in the 360-view? (No ICD-10 mapping is triggered; staff sees a "No diagnoses available for coding" message)
- What if all candidate codes have confidence below 0.5? (Codes are still presented with red indicators and a warning prompting staff to manually enter the correct code)

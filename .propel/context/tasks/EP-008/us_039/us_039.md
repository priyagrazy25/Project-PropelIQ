# User Story - US_039

## Story ID
- ID: US_039

## Story Title
- CPT Code Mapping

## Description
- As a clinical staff member, I want the system to map CPT codes from procedures and encounters identified in the aggregated patient data, presenting top-3 candidate codes ranked by confidence, so that I can verify and approve accurate billing codes efficiently.

## Acceptance Criteria
1. **Given** the 360-Degree Patient View contains procedures and encounters, **When** CPT mapping runs, **Then** the system maps CPT codes using classification models and reference table lookup per AIR-005.
2. **Given** mapping produces results, **When** candidates are displayed, **Then** the top-3 codes are ranked by confidence score with color-coded indicators (green/amber/red).
3. **Given** mapped CPT codes, **When** stored, **Then** each MedicalCode record includes CodeType (CPT), Code, Description, ConfidenceScore, and Status ("Suggested") per DR-007.
4. **Given** all AI-generated CPT codes, **When** created, **Then** they enter with "Suggested" status requiring explicit staff verification per AIR-S04.
5. **Given** the coding interface, **When** staff views ICD-10 and CPT codes together, **Then** both code types are displayed in a unified view on SCR-018 with their respective confidence scores.

## Edge Cases
- What happens when no procedures or encounters are identified? (No CPT mapping is triggered; staff sees a "No procedures available for coding" message)
- What if a procedure maps to multiple valid CPT codes with similar confidence? (All top-3 are presented; staff selects the most appropriate code based on clinical context)
